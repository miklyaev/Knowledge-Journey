# Предложения по внедрению RAG (Retrieval-Augmented Generation)

Основываясь на архитектуре проекта (образовательная платформа "Knowledge Journey" с интерактивным ИИ-преподавателем, генерирующим тесты и объяснения), внедрение RAG может значительно повысить качество и точность обучения.

## 1. Где в проекте можно применить RAG?

**А. Строгая привязка к учебным материалам (Устранение галлюцинаций)**
Сейчас ИИ (GigaChat/YandexGPT) опирается только на свои внутренние знания и системный промпт из `themeCollection.json`. 
* **Применение:** Загрузить в векторную базу данных реальные лекции, методички университета, актуальную документацию. Когда студент задает вопрос или просит объяснить тему, ИИ будет сначала находить релевантные куски из **ваших** материалов и генерировать объяснение и тесты (`journey`) строго на их основе.

**Б. Контекстная проверка заданий со свободным ответом (`free-response`)**
В системе есть задания типа `free-response`, которые оцениваются высоко (10 баллов).
* **Применение:** При проверке ответа студента ИИ может извлекать эталонный ответ или критерии оценки из базы знаний (RAG) и сравнивать ответ студента с ними, давая более объективную и аргументированную обратную связь.

**В. Персонализированный контекст (Память о прошлых ошибках)**
* **Применение:** Сохранять историю ответов студента (особенно ошибки в тестах) в векторную БД. Когда студент переходит к новой теме, RAG может подтягивать его прошлые слабые места, и ИИ-преподаватель будет адаптировать объяснение: *"Помнишь, в прошлой теме мы обсуждали X? Здесь применяется похожий принцип..."*

## 2. Какую технику RAG лучше применить?

Для образовательной платформы с техническим уклоном (C#, JS, Node.js) базовый (Naive) RAG будет давать сбои из-за специфичной терминологии. Рекомендую использовать следующие продвинутые техники:

### А. Hybrid Search (Гибридный поиск: Векторный + BM25) — *Обязательно*
Так как студенты изучают программирование, они будут использовать точные термины (например, `useEffect`, `Entity Framework`, `IQueryable`). Чистый векторный поиск (семантический) часто плохо ищет точные совпадения по коду или специфичным терминам. 
* **Решение:** Использовать гибридный поиск, который объединяет семантическую близость (векторы) и точное совпадение ключевых слов (BM25).

### Б. Metadata Filtering (Фильтрация по метаданным) — *Обязательно*
У вас уже есть четкое разделение на темы в `themeCollection.json` (`csharp`, `aspnet`, `js_node`).
* **Решение:** При загрузке документов в векторную БД каждому чанку (куску текста) нужно присваивать метаданные (например, `{"theme": "csharp", "level": "junior"}`). Когда студент задает вопрос в рамках темы `csharp`, поиск (retrieval) должен жестко фильтроваться только по этой теме, чтобы ИИ случайно не привел пример на JavaScript.

### В. Parent-Child Chunking (Иерархические чанки) — *Рекомендуется для обучения*
Для качественного объяснения ИИ нужен широкий контекст, но искать лучше по узким, конкретным фактам.
* **Решение:** Документ разбивается на крупные куски (Parent - например, целая глава лекции), а они бьются на мелкие (Child - конкретные определения). Векторизуются мелкие куски. Когда студент спрашивает про конкретный термин, система находит мелкий чанк, но передает в LLM весь родительский чанк. Это позволит ИИ-преподавателю дать развернутый ответ с контекстом, а не просто сухое определение.

## 3. Как это технически интегрировать в текущий код?

1. **Векторная БД:** Так как у вас уже используется реляционная БД (MySQL/PostgreSQL, судя по `dbservice.js` и `.sql` файлам), вы можете использовать **pgvector** (если это PostgreSQL), чтобы не поднимать отдельный сервис. Либо добавить легковесную **ChromaDB** / **Qdrant** в ваш `docker-compose.yml`.
2. **Изменения в `backend/server.js`:**
   В эндпоинтах `/api/gigachat/generate` и `/api/yandexgpt/generate` перед отправкой запроса к LLM:
   ```javascript
   // 1. Получаем вопрос студента (prompt)
   // 2. Делаем поиск по векторной БД с фильтром по текущей теме (topicPrompt)
   const relevantContext = await vectorDb.search(prompt, { theme: currentTheme });
   
   // 3. Формируем обогащенный промпт
   const augmentedPrompt = \`
     Опираясь на следующие учебные материалы:
     \${relevantContext}
     
     Ответь на вопрос студента и сгенерируй тест: \${prompt}
   \`;
   ```
3. **Интерфейс (`AIAssistant.tsx`):** Можно добавить индикатор для студента: *"Ответ сгенерирован на основе лекции №4"*, возвращая источники (sources) из бэкенда вместе с ответом.
