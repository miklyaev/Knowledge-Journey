# Dev Notes

## 2026-07-11 — Рефакторинг RAG и Админка

**Область:** Backend, Frontend, RAG

**Что изменилось:**
- **Backend**:
  - Добавлен эндпоинт `/api/admin/login` для авторизации администратора (логин/пароль в `.env`).
  - Добавлен эндпоинт `/api/pdf/by-theme/:themeId` для получения привязанного PDF к теме.
  - В `dbService.js` добавлен метод `getPdfByThemeId` для поиска последней привязки PDF по ID темы.
- **Frontend**:
  - **Навигация**: В `TopBar` добавлен выпадающий список «Настройка» с пунктом «Привязка к источнику».
  - **Админка**: Создана страница `/admin/sources` для управления привязками PDF к темам.
    - Доступ через авторизацию администратора.
    - Возможность выбора темы, загрузки PDF и просмотра извлеченных разделов.
  - **Маршрут обучения**:
    - Удалены элементы управления загрузкой PDF (путь, обзор, применить).
    - Реализована автоматическая загрузка данных RAG (pdfId и разделы) при выборе темы, если включен чекбокс «Привязка к источнику».
    - Если для темы нет привязанного источника, выводится соответствующее уведомление.

**Зачем / контекст:**
Улучшение UX: обычный пользователь больше не должен самостоятельно искать и загружать PDF-файлы. Все привязки настраиваются администратором заранее.

## 2026-07-08 — Интеграция RAG с локальными PDF


**Область:** Backend, Frontend, Infrastructure, RAG

**Что изменилось:**
- **Infrastructure**: Добавлен сервис **ChromaDB** в `docker-compose.yml` для векторного поиска.
- **Backend (RAG)**: Создан модуль `backend/rag/` для парсинга PDF (`pdf-parse`), чанкинга по разделам и векторизации через GigaChat API.
- **Backend (API)**: Добавлены эндпоинты `/api/pdf/upload`, `/api/pdf/sections/:pdfId` и `/api/rag/retrieve`.
- **Backend (LLM)**: Модифицированы генераторы ответов для инъекции контекста из PDF в системный промпт.
- **Database**: Создана таблица `t_pdfs` для хранения метаданных и структуры разделов PDF.
- **Frontend**: В `KnowledgeJourney` добавлен UI для управления источниками (чекбокс, загрузка PDF, выбор раздела). `AIAssistant` теперь поддерживает RAG-контекст.

**Зачем / контекст:**
Позволяет пользователям использовать собственные PDF-документы (например, учебники по C#) как базу знаний для ИИ-помощника, обеспечивая более точные и контекстные ответы.

## 2026-07-08 — Настройка инициализации БД

**Область:** Infrastructure, MySQL

**Что изменилось:**
- **MySQL (`mysql/Dockerfile`):** Добавлено копирование скрипта `backend/t_add_user.sql` в директорию инициализации `/docker-entrypoint-initdb.d/` под именем `3_add_user.sql`.

**Зачем / контекст:**
Автоматическое создание пользователя `mikser` и предоставление ему прав доступа после создания таблиц при первом запуске контейнера базы данных. Это решает проблему `Access denied for user 'mikser'`, возникавшую из-за отсутствия пользователя в чистой базе.

## 2026-07-07 — Оптимизация логирования

**Область:** Backend, Infrastructure

**Что изменилось:**
- **Backend (`server.js`):** Полностью удален механизм записи логов в файл `server.log`. Удалены перехватчики `console.log/error/warn` и функция `logToFile`.
- **Infrastructure:** Удален файл `backend/server.log`. Теперь логирование осуществляется исключительно через стандартные потоки вывода (stdout/stderr), что позволяет Docker эффективно управлять логами (сбор, ротация, ограничение размера).

**Зачем / контекст:**
Предотвращение неограниченного роста файла `server.log` внутри контейнера и использование стандартных механизмов Docker для управления логами.

## 2026-07-07 — Рефакторинг: Переход на обязательное использование MySQL
**Область:** Backend, Frontend, Infrastructure

**Что изменилось:**
- **Backend (`dbservice.js`):** Удален флаг `dbEnabled`. Теперь база данных является обязательным компонентом. Увеличен таймаут подключения до 10 секунд.
- **Backend (`server.js`):** Полностью удалена логика фолбэка на файловую систему (папки `users/` и `reports/`). При неудачном подключении к БД сервер завершает работу с кодом 1.
- **Frontend (`src/app/page.tsx`):** Добавлена блокирующая проверка статуса БД на главной странице. При отсутствии подключения выводится техническое сообщение об ошибке.
- **Документация:** Обновлен `README.md`, актуализированы требования к БД.
- **Очистка:** Удалены папки `backend/users` и `backend/reports`.

**Зачем / контекст:**
Повышение надежности системы и упрощение архитектуры за счет отказа от дублирующих механизмов хранения данных.

## 2026-07-06 — Исправление подключения к API на VDS
- **docker-compose.yml**: Синхронизированы порты бэкенда (`3031:3031`) и обновлена переменная `NEXT_PUBLIC_API_BASE_URL` на внутренний адрес Docker (`http://backend:3031`).
